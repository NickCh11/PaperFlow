# Actions execution and spending controls

PaperFlow uses standard Ubuntu runners. Existing spending controls, subscriptions
and repository visibility are not changed by the release-only configuration.

## Draft and ready PRs

Draft updates run Python/JVM checks, Lint and Sonar with JVM coverage. Ready PRs
and subsequent pushes automatically run native compilation, both emulator APIs,
compiled/R8/manifest/native verification and Sonar with current-run coverage.
The optional full-validation label can request a full draft run; it is unnecessary
for a ready PR. Fast checks cannot satisfy the protected PR gate.

Main/master pushes and merge-queue entries retain full validation. There is one
shared compilation/native-check job rather than three debug/release APK builds.
No release APK or downloadable debug APK artifact is generated by CI. Emulator
jobs still build their own temporary debug/test APKs and keep coverage/reports.

## Release publishing

Only publishing a stable GitHub Release starts the three signed production APK
builds. Tag pushes and manual CI dispatch do not. The release reuses native
caches, omits validation-only native artifacts, and checks successful full CI on
the exact main SHA before starting. APKs are rebuilt from that source rather
than downloaded from expiring CI build artifacts. One release executes at a time.

Reports/native artifacts generally last three days (native coverage objects one
day). Signed release staging lasts three days; R8 release mappings last 30 days.
Release assets remain attached to their GitHub Release. Weekly model health
checks are unchanged. Full model-byte downloads remain manual.

See [BUILD.md](BUILD.md#github-releases) for secrets, first release and failures.
